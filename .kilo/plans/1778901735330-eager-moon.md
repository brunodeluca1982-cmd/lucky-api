# Plan: Investigate Smart Itinerary Generation Failure

## Problem
User reports "Roteiro inteligente" (smart itinerary) is not being generated.

## Investigation Findings

### Key Files Identified
- `artifacts/api-server/src/routes/friend-itinerary.ts` - Main itinerary route handler
- `artifacts/mobile/supabase/migrations/20260408_roteiro_itens_user_itinerary_id.sql` - Database schema for itinerary items
- Multiple specification files in `attached_assets/` defining itinerary engine requirements

### Critical Constraints (from spec files)
1. **Data Source Strictness**: Only places from Supabase tables: `restaurantes`, `o_que_fazer_rio`, `lucky_list_rio`, `stay_hotels`
2. **No External Fallbacks**: Forbidden - Google Places fallback, external APIs, LLM-generated locations
3. **Image Integrity**: Only use `photo_url` from Supabase; no external image fetching
4. **Validation Layer**: Each item must have valid `source_table` and `id` from Supabase before inclusion
5. **Hotel Persistence**: Selected hotel must appear in every day as "HOSPEDAGEM"
6. **Restaurant Timing Rules**: almoço→food only, tarde→no restaurants, etc.

### Potential Failure Points
1. **Empty result after validation**: If itinerary items fail Supabase validation, they get removed, potentially leaving empty itinerary
2. **Missing hotel handling**: If hotel selection logic fails, itinerary generation may abort
3. **Image fallback removal**: Previous image fallback mechanisms now forbidden, may cause item rejection
4. **Query performance**: Strict JOINs against 4 Supabase tables may timeout or return no results
5. **Cache invalidation**: `places_cache` only valid if referencing valid Supabase `place_id`

## Recommended Investigation Steps

1. Check `friend-itinerary.ts` for:
   - Validation logic that filters out items
   - Error handling that silently fails
   - Database query conditions that may return empty sets

2. Verify Supabase data:
   - Confirm tables `restaurantes`, `o_que_fazer_rio`, `lucky_list_rio`, `stay_hotels` have data for user's location/dates
   - Check if `place_id` references are intact

3. Review logs for:
   - Validation failures (items removed due to missing source_table/id)
   - Database query errors or timeouts
   - Hotel selection failures

4. Test with minimal input:
   - Generate itinerary with only hotel selected
   - Generate with single day, single activity type

## Fix Strategy (if validation is too strict)
- Add debug logging to validation step to identify which items fail and why
- Ensure fallback behavior shows placeholder UI rather than empty itinerary
- Verify hotel is always included regardless of other validation

## Next Actions
1. Read `friend-itinerary.ts` implementation
2. Identify validation/filtering logic
3. Check for silent failures or empty result handling
4. Propose fix based on root cause
